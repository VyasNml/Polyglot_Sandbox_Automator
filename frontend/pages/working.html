Step by Step

Execution Pipeline

01

Client Sends Execution Request

The client (browser or API consumer) sends a POST /api/execute request with the code payload, language identifier, and optional configuration like timeout duration or memory limits. All requests are validated against a strict schema.

02

FastAPI Validates and Routes

The FastAPI backend validates the payload, sanitizes inputs, and routes the request to the appropriate language handler. Language-specific Docker images are selected (e.g., python:3.12-slim, gcc:latest).

03

Container is Provisioned

Using the Docker SDK for Python, a new ephemeral container is spawned with strict resource constraints: CPU limits, memory caps, no network access, and read-only filesystem mounts. Each container is assigned a unique execution ID.

04

Code is Injected and Executed

The user's code is written to a temporary file and mounted into the container. The sandbox runs the appropriate interpreter or compiler. A timeout watchdog monitors execution duration and sends SIGKILL if the limit is exceeded.

05

Results are Captured

stdout, stderr, exit code, execution time, and memory consumption are collected by the result aggregator. The data is structured into a JSON response payload and returned to the client with appropriate HTTP status codes.

06

Container is Destroyed

Post-execution, the container is immediately removed (docker rm --force). No state persists between executions. The ephemeral design ensures complete isolation and prevents any residual data leakage between users.
